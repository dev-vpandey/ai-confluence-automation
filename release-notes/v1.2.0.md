# Release Notes — v1.2.0

**Release date:** 2026-05-22
**Status:** Production Ready
**Audience:** Engineers and data practitioners using the `confluence-automation` Claude Code skill

---

## Summary

Replaces cookie-only authentication with a PAT token as the primary auth method. Set `CONFLUENCE_TOKEN` once in `~/.zshrc` and the script handles the rest — no manual cookie refresh each day. Cookie session is retained as a fallback for environments where the env var isn't set.

**Impact:** Low — no commands or page operations changed
**Breaking changes:** None
**Migration required:** No
**Action required:** Optional — set `CONFLUENCE_TOKEN` in `~/.zshrc` to switch to PAT auth

---

## What's new

### PAT token authentication

`confluence_page.py` now supports Bearer token auth via a `CONFLUENCE_TOKEN` environment variable. `get_session()` checks for the env var first — if set, it creates a session with an `Authorization: Bearer <token>` header. If not set, it falls back to the existing cookie session from `~/.confluence-session`.

**Before:** Cookie session required manual refresh every ~24 hours via `./refresh-auth`.
**After:** Set the token once; it doesn't expire on a daily cycle.

**Setup:**

```bash
# Generate a PAT: Confluence profile → Personal Access Tokens → create with read/write permissions
echo 'export CONFLUENCE_TOKEN=your_pat_token' >> ~/.zshrc
source ~/.zshrc
```

**Who benefits:** Anyone running the skill regularly — no more daily `./refresh-auth` interruptions.

### Auth-aware 401 error messages

On a 401, the script now returns a message specific to which auth method is active:
- PAT active → tells you to rotate `CONFLUENCE_TOKEN` in `~/.zshrc`
- Cookie fallback active → tells you to run `./refresh-auth --guided`

## Known issues

- Cookie auto-extraction (`./refresh-auth` with no flags) is still not functional — use `--guided` or `--manual` for cookie refresh. Less relevant now that PAT is the default path.
